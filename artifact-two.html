Artifact Background

For this milestone, I improved how Clearspace handles deep folders and calculates folder sizes. I built Clearspace in August 2026 as a Windows file manager using C# and WPF. It supports browsing, search, tags, and file operations. This work builds on my Artifact 1 changes and focuses on algorithms and data structures: better traversal, a disk usage viewer, and more reliable index recovery.

Reason for Selection and Improvements

I chose Clearspace because a drive can hold millions of files nested many levels deep, and the app must give correct results without freezing. Before, indexing stopped at 32 folder levels and fallback search stopped at 24, so the same folder could give different results. Now indexing uses a stack and search uses queues, with no depth limits, and background work can be canceled when it is no longer needed. Both handle folder links the same way, which prevents endless loops.

Folder sizes are now calculated in one bottom-up pass. Each folder's total is added to its parent once, which is O(n) instead of O(n × d) for walking up from every file, where d is folder depth. Totals are stored in simple arrays, and the treemap caches its layout and skips off-screen branches. Each drive also tracks its own index health, so one drive missing changes does not block search on the others. A new index also picks up changes made while it was being built. The indexing page now shows entry counts, storage use, scan activity, and why a scan is waiting, so users can see the work happening in the background.

Course Outcomes

This work shows the outcome of using algorithms to design solutions while weighing tradeoffs. Deeper scans take longer and caches use memory, but results are now complete and faster to repeat. It also shows the use of sound tools and techniques: tests cover deep folders, cancellation, caching, layout, and index updates, and all 158 tests passed. Safe link handling and checked size math reflect a security mindset. These show progress toward the outcomes, not full mastery.

My focus is still algorithms and data structures. I added cache fixes, per-drive recovery, and clearer indexing feedback because the main changes were not useful without them. The database work is a separate artifact.

Reflection on Learning and Challenges

My biggest lesson was that fast results still have to be correct. Removing depth limits added work, so cancellation and memory limits mattered more, and caching needed a clear rule for when data was out of date. The disk viewer froze and flickered on crowded folders, and at one point labels moved without their blocks. That taught me the camera, the drawn shapes, and the click areas must all match the same frame, and that I should test while things move, not just on a still screen.

The indexing page taught me about clear feedback. A percentage based on found folders can drop when more folders turn up, and an empty progress bar did not explain why scanning stopped. Showing the reason, the retry time, and a Scan now button made it clearer. Tests, including a 48-level folder test, made rechecking easy, but they do not prove smooth performance on every drive. Next, I will use instructor feedback and keep testing on real drives.
