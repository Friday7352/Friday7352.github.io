Algorithms, Software Engineering, and Databases

The capstone brought software engineering, algorithms, and database concepts together in one application. In the software-design enhancement, I separated search coordination, navigation loading, and sidebar state into focused components. I also replaced Boolean file-operation results with explicit success, cancellation, and failure outcomes. This made the components easier to test and allowed the interface to distinguish a canceled operation from an error.

For Outcome 3, evaluating computing solutions through algorithmic principles and design tradeoffs, I improved file discovery and folder-size calculation. Explicit stacks and queues replaced arbitrary traversal-depth limits. A bottom-up pass calculates folder totals in O(n) time by adding each subtree total to its parent once. Cached layouts reduce repeated work in the disk-usage viewer. These choices also introduce costs: deeper traversal can require more work, and caches need memory limits and rules that prevent stale results. I learned to evaluate completeness and responsiveness together.

Outcome 4 concerns using established techniques and tools to deliver useful computing solutions. I applied C#, WPF, automated regression tests, and SQLite to Clearspace's actual workflows. The database enhancement replaced JSON tag storage with related tables, constraints, indexes, and transactions. The migration retains the original JSON, and bulk changes either commit together or roll back. This work helped me understand how database design supports behavior users depend on, rather than functioning as an isolated technical exercise.

My first structured testing experience came in CS 320, where I wrote JUnit tests in Java for Contact, Task, and Appointment services. Each test matched a rule from the requirements: contact IDs had to be unique, task names could not exceed 20 characters, and appointments could not be scheduled in the past. A coverage tool in Eclipse showed that my tests exercised over 80 percent of the code. The more lasting lesson was to try to break my own code instead of assuming it worked, because developers tend to overlook problems in their own work. Clearspace's tests for cancellation, wrong passwords, tampering, and failed file replacement apply the same habit to a much larger application.

Security and Professional Responsibility

Outside the capstone, my CompTIA A+ certification and my ongoing Network+ studies ground security in everyday operations. Systems and networks must be configured, maintained, and supported by people, and weaknesses often appear where those routines fail. That perspective shaped how I approached the security work in Clearspace.

Outcome 5 concerns anticipating vulnerabilities and protecting data and resources. I applied that mindset through parameterized database queries, input validation, safe handling of folder links, and tests for failure cases. The file-protection enhancement uses authenticated encryption and password-derived protection without storing plaintext passwords or unwrapped file keys in the database. Tests cover wrong passwords, tampering, and failures around file replacement.

I learned to consider recovery as part of security. A database transaction cannot also commit a Windows file replacement, so the database and filesystem can be left in different states after an interruption. Documenting that boundary helped me avoid overstating the protection offered by the feature. The milestone implementation also has explicit limits, including supported local NTFS files and a 64 MiB per-file limit. Passing tests provides evidence for the cases exercised; it does not replace an independent security review.

Algorithms & Data Structures

Completed

Clearspace Disk Usage and Indexing Enhancement

I enhanced Clearspace with a disk usage analyzer and improved the algorithms behind file discovery, folder-size calculation, and index recovery. Stack and queue traversals replace arbitrary depth limits, while a bottom-up pass calculates folder totals in O(n) time using indexed parent relationships.

Compact arrays, cached geometry, and subtree ranges reduce repeated layout work and let the viewer skip off-screen branches. Per-drive recovery keeps healthy indexes available when another drive needs updating. The indexing page explains scan activity, waiting states, storage usage, and the entries actually indexed.

The September 23 verification run passed 158 Release tests. Tests cover deep traversal, cancellation, cache replacement, concurrent updates, layout properties, and dense scenes. The narrative discusses memory and responsiveness tradeoffs, learning, and limitations; these tests do not guarantee smooth performance on every drive.

Databases

Completed

Clearspace SQLite Storage and File Protection

I replaced Clearspace's JSON tag storage with a relational SQLite database. Tags, paths, and their assignments use primary keys, foreign keys, and indexes to keep relationships consistent and support efficient lookups. Parameterized queries treat names and paths as data, and transactions save bulk changes together or roll them back together. A first-run migration retains the original JSON.

I also added password-protected files using AES-256-GCM encryption and database records for password verification and lock state. Each encrypted file carries its protected recovery header, allowing it to be unlocked with its password after a rename or loss of the local database. The database stores neither plaintext passwords nor unwrapped file keys.

The supplied Artifact Three archive includes the newer file and folder locking implementation described in the final narrative. Its saved final test report records 283 tests: 280 passed and 3 failed. The earlier October 1 report records 251 passing tests. These are archived results; the supplied ZIP has not been retested as part of portfolio publishing.

The enhancement demonstrates Course Outcomes 3, 4, and 5 through design tradeoffs, established computing tools, and a security mindset. The narrative explains learning and limitations, including the 64 MiB per-file limit, local NTFS requirement, and the separate filesystem and database commits.
