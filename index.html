Algorithms & Data Structures

Completed

Clearspace Disk Usage and Indexing Enhancement

I enhanced Clearspace with a disk usage analyzer and improved the algorithms behind file discovery, folder-size calculation, and index recovery. Stack and queue traversals replace arbitrary depth limits, while a bottom-up pass calculates folder totals in O(n) time using indexed parent relationships.

Compact arrays, cached geometry, and subtree ranges reduce repeated layout work and let the viewer skip off-screen branches. Per-drive recovery keeps healthy indexes available when another drive needs updating. The indexing page explains scan activity, waiting states, storage usage, and the entries actually indexed.

The September 23 verification run passed 158 Release tests. Tests cover deep traversal, cancellation, cache replacement, concurrent updates, layout properties, and dense scenes. The narrative discusses memory and responsiveness tradeoffs, learning, and limitations; these tests do not guarantee smooth performance on every drive.

Databases

Completed

Clearspace SQLite Storage and File Protection

I replaced Clearspace's JSON tag storage with a relational SQLite database. Tags, paths, and their assignments use primary keys, foreign keys, and indexes to keep relationships consistent and support efficient lookups. Parameterized queries treat names and paths as data, and transactions save bulk changes together or roll them back together. A first-run migration retains the original JSON.

I also added password-protected files using AES-256-GCM encryption and database records for password verification and lock state. Each encrypted file carries its protected recovery header, allowing it to be unlocked with its password after a rename or loss of the local database. The database stores neither plaintext passwords nor unwrapped file keys.

The October 1 Milestone Four verification passed 251 Release tests covering migration, constraints, rollback, persistence, wrong passwords, tampering, and failures around file replacement. A separate dialog check confirmed that unlocking restored the original bytes. This portfolio presents that verified submission snapshot; later application changes are outside this package.

The enhancement demonstrates Course Outcomes 3, 4, and 5 through design tradeoffs, established computing tools, and a security mindset. The narrative explains learning and limitations, including the 64 MiB per-file limit, local NTFS requirement, and the separate filesystem and database commits.
