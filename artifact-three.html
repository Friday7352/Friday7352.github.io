Artifact Background

For this milestone, I changed how Clearspace saves its data and added password locks for files and folders. I built Clearspace in August 2026 as a Windows file manager using C# and WPF. It supports browsing, search, tags, and file operations. Tags now live in a SQLite database, and the same database tracks locked files, locked folders, and the master password check.

Reason for Selection and Improvements

I chose Clearspace because I use its saved data every day. Before, all tags were kept in one JSON file that was rewritten on every change. Now tags are stored in three tables. Keys stop duplicate or broken links, an index makes tag searches fast, and changes to many files are saved all at once or not at all. The first run imports the old JSON and keeps the original file. Every query uses parameters, so text that looks like SQL is saved as plain text.

Locking is what made the database worth having. A user can right-click a file or folder and lock it with a password. Each file gets its own AES-256-GCM key, protected by a key made from the password with PBKDF2 (Microsoft, n.d.-a; OWASP Foundation, n.d.). The database never stores the password. Each locked file carries its own header, so it can still be unlocked after a reinstall, a Windows reset, or a move to another PC.

The database grew in small steps that keep existing data. Later versions added locked folders and files unlocked for a short visit. A locked folder asks for the password before it opens. Its files stay unlocked while the user is inside, and Clearspace locks them again after the user leaves, using a short-lived key protected by Windows (Microsoft, n.d.-b). Locked items also work in File Explorer, with a lock icon and right-click options to lock, unlock, remove a lock, or change a password.

Course Outcomes

My Module One plan chose Outcomes 4, 5, and 3. It planned to move tags into a database, store lock data and a password check, and add file locking. All of that is done, and I added folders, multi-select, automatic re-locking, File Explorer support, password changes, and recovery after a reset. Some limits remain: files can be up to 64 MB on a local NTFS drive, and links and cloud files are skipped. I also tried to make File Explorer ask for a password before opening a locked folder, but Windows does not support that well, so I removed it.

For Outcome 4, I used SQLite, step-by-step database upgrades, .NET encryption, and automated tests. The suite has 283 tests, 56 of them for locking.

For Outcome 5, I planned for things going wrong. A wrong password or a changed file is rejected without harm, and a typo can never become the key that files are locked with. Some risks remain. Locking does not erase older copies in backups or caches, unlocked files can be read until they lock again, and not having a minimum password length allows weak passwords.

For Outcome 3, each choice had a cost. The database added upgrade work but gave me rules and safe saves. Locking files in place keeps names visible but is faster than packing a whole folder. Unlocking in place lets any program open the files, but they stay readable during the visit.

Reflection on Learning and Challenges

My biggest lesson was that protecting files is mostly about not losing them. A database save cannot include a file change, so each lock records recovery data, writes and checks a copy, replaces the file, and then updates the database. Because each file carries its own header, losing the database never locks a file away.

Asking “what if” found my worst bug. The first version checked the saved password before trying the file, so after a reset with a new password, older files would have been refused. Now it checks the file itself and offers to switch it to the current password. I also learned when to stop: the File Explorer password prompt never worked reliably, so I chose a simpler design. Finally, an early “nothing happens” report came from an old installed copy, so I now check which build is running before I debug. Next, I will use instructor feedback and consider a recovery key and a password strength warning.
