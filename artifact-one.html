Artifact Background

Clearspace is a Windows file manager I built in August 2026 using C# and Windows Presentation Foundation (WPF). It lets users browse folders, search for files, add tags, and copy, move, rename, and delete files. For this milestone, I kept all of those features and improved how the code is organized, how it reports the results of file operations, and how it is tested.

Why I Chose Clearspace and What I Improved

I chose Clearspace because it is a real application with several parts that depend on each other: a user interface, searches that run in the background, and file operations that can fail in many ways. That gave me room to make actual design decisions instead of just adding a new screen or button.

Separating responsibilities. The project already split its code into models, commands, and services, but one class, MainViewModel, was doing too much. I moved search handling into SearchCoordinator, folder loading into NavigationCoordinator, and sidebar state into SidebarViewModel. Each piece can now be read and tested on its own, without starting the whole interface. The trade-off is more classes to navigate, but each one is smaller and easier to understand.

Clearer results for file operations. Copy, move, rename, and delete used to return only true or false. They now return a FileOperationResult, which says whether the operation succeeded, was cancelled, or failed. It also keeps the Windows error details and a message for the user. This matters because canceling a copy should not look like a permission error. I also updated every place that calls these operations, since better information is useless if the interface ignores it.

Automated tests. The project now has 87 automated tests, and all of them pass in the Release configuration. They cover search cancellation and duplicate removal, tag saving and assignment, indexing edge cases, and file-operation outcomes. The tests use controlled data, so I can simulate failures without deleting or moving real files. They give repeatable proof that these behaviors work, but they do not prove that every interaction in the interface is correct.

Together, these changes show refactoring, designing code so it can be tested, handling timing problems in background work, and writing automated tests.

Reflection on Learning and Challenges

The biggest lesson was to decide what each component owns before moving any code. Search was the hardest part because several sources can return results at different times. Canceling an old search is not enough. Late results from that old search also have to be blocked from replacing the results of a newer one. Separating the coordinator from its sources let me recreate these timing problems in controlled tests.

Testing also caught two bugs that my code review missed. A filter-only search such as ext:txt could skip results from subfolders, because the app treated “the index covers this folder” as proof that “the index can answer this query.” Also, clearing a search restored the folder’s items but not its status message. I fixed both and added regression tests, which are tests that make sure a fixed bug stays fixed.

Course Outcomes

Collaboration: My code review video and the section-header comments in the source files make the code easier for others to read and review. This milestone did not involve working with a team.

Communication: The code review, my implementation notes, and this narrative explain why I made each change and where its limits are.

Algorithms and design trade-offs: Splitting up MainViewModel meant weighing more classes against clearer ones. The algorithm work, including traversal depth and folder-size calculations, is planned for Milestone Three.

Well-founded techniques and tools: I applied separation of responsibilities and repeatable testing to an existing application.

Security mindset: Handling cancellation and errors explicitly avoids misleading feedback when files are involved. However, this does not guarantee that a partly finished Windows operation can be undone. SQLite tag storage will be handled in the database milestone.
